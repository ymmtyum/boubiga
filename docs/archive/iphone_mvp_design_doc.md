# iPhone特化アプリ 設計ドキュメント

仮称：未定

## 0. 方向転換の前提

当初はガジェット全般のコレクションアプリとして検討していたが、MVPではスコープを大きく絞り、**iPhoneに特化した所有・使用感・買い替え判断ツール**として設計する。

ガジェット全般を対象にすると、ガジェット好き・スペック好き向けに消費されやすく、細かい分類や未対応商品への批判も受けやすい。初期プロダクトとしては、一般ユーザーにも関係が深く、買い替え周期・中古相場・バッテリー劣化・容量不足といった明確な課題があるiPhoneに特化する方が、価値を届けやすい。

このアプリは、スペック比較アプリではない。ユーザー自身のiPhone遍歴・使用感・不満・バッテリー状態などを記録し、自分に合うiPhoneと買い替えタイミングを見つけるためのツールである。

---

## 1. コンセプト

### 1.1 コアコンセプト

**自分のiPhone遍歴から、次のiPhone選びを考えるアプリ。**

または、より機能寄りに表現すると以下。

**iPhoneの所有履歴・使用感・買い替え理由を記録することで、自分に合うモデルと買い替えタイミングを見つけるアプリ。**

### 1.2 コア価値

このアプリのコアは、iPhoneを登録できることではなく、**その人自身の使用感・不満・買い替え理由・バッテリー状態などの一次情報が蓄積されること**にある。

ただし、初回登録時にレビューや感想は求めない。まずは現在使っているiPhoneを自動検出し、マイiPhoneに追加するだけで完了させる。入力すべき情報は後からタスクとして提示し、ユーザーが少しずつ潰していける設計にする。

## 2. 初期MVPの基本方針

### 2.1 初期登録は極限まで軽くする

インストール直後に、現在使っているiPhoneを自動検出する。

初回登録時には、以下のような情報は聞かない。

- 購入日
- 購入価格
- 満足度
- 使用感
- 買い替え意向
- バッテリー最大容量

まずは、現在使っているiPhoneをマイiPhoneに追加することを優先する。

### 2.2 マイiPhoneを肥やす気持ちよさを優先する

登録体験は「フォーム入力」ではなく、「自分のiPhoneがアプリ内に並ぶ」体験にする。

初回は以下のような流れを想定する。

1. アプリを起動する
2. 現在のiPhone情報を検出する
3. 推定モデル・容量・空き容量・iOSバージョンなどが表示される
4. 「マイiPhoneに追加する」を押す
5. マイiPhoneに登録される
6. 不足情報は赤ドット付きタスクとして残る

## 3. タブ構成

### 3.1 初期MVPでは2タブ構成にする

従来の5タブ構成は採用しない。

旧案：

1. マイギア
2. 遍歴
3. 探す
4. 分析
5. 設定

iPhone特化MVPでは、以下の2タブに絞る。

1. **マイiPhone**
2. **探す**

設定は独立タブにせず、マイiPhone画面右上の歯車アイコンから遷移する。

### 3.2 マイiPhone

アプリのホーム兼ダッシュボード。

ここに以下を集約する。

- 現在のiPhone
- 過去のiPhone
- 登録日
- 最終更新日
- 端末情報
- バッテリー最大容量
- バッテリー確認日
- 空き容量
- iOSバージョン
- 使用感ログ
- 確認待ちタスク
- 簡易分析
- iPhone遍歴

### 3.3 探す

次のiPhone選びのためのタブ。

初期MVPでは薄く始める。

想定要素：

- iPhoneモデル一覧
- シリーズ別一覧
- 買い替え候補
- 自分の不満から見る候補
- 将来的には、似た使い方の人の実使用データ

### 3.4 設定

設定はタブではなく、マイiPhone右上の歯車アイコンから遷移する。

想定要素：

- 通知設定
- データ管理
- プライバシー
- Pro機能
- エクスポート
- アカウント

## 4. 自動取得する端末データ

iPhoneアプリとしてインストールされる以上、自動で取れる情報は初回体験に活用する。

### 4.1 初期MVPで自動取得したい項目

1. 現在使っているiPhoneの推定モデル
2. ストレージ容量
3. 空き容量
4. iOSバージョン
5. バッテリー残量
6. 充電状態

### 4.2 推定モデル

iOSの標準APIだけで「iPhone 16 Pro」のような販売名を直接取得するのではなく、ハードウェア識別子を取得し、自前のマスタで変換する。

例：

```text
ハードウェア識別子
↓
自前マスタ変換
↓
推定モデル名
```

UX上は、確定ではなく「推定」として扱う。

表示例：

```text
このiPhoneを検出しました

推定モデル：iPhone 16 Pro
容量：256GB
空き容量：78GB
iOS：18.5
バッテリー：73%
状態：充電中
```

ボタン：

```text
[マイiPhoneに追加する]
[モデルを変更する]
```

### 4.3 ストレージ容量・空き容量

ストレージ容量と空き容量は自動取得する。

表示上は生の数値ではなく、ユーザーに分かりやすい単位に丸める。

例：

```text
容量：256GB
空き容量：78GB
```

空き容量は、将来的に容量不足による買い替え判断に使う。

### 4.4 iOSバージョン

iOSバージョンは自動取得する。

将来的には、以下のような判断材料に使える。

- 最新iOS対応状況
- 今後のアップデート対象外リスク
- 古いiOSによる不便さ
- iOSアップデート後の使用感変化

### 4.5 バッテリー残量・充電状態

バッテリー残量と充電状態は自動取得する。

ただし、これは現在の残量・現在の充電状態であり、バッテリー劣化度ではない。

例：

```text
バッテリー：73%
状態：充電中
```

## 5. バッテリー最大容量の扱い

### 5.1 バッテリー劣化度は自動取得しない

通常のApp Store向けアプリでは、バッテリー最大容量・劣化度・充放電回数は取得できない前提で設計する。

そのため、バッテリー最大容量はユーザーによる手入力とする。

### 5.2 スクショ誘導・設定誘導にする

ユーザーには、iPhoneの設定アプリで確認してもらう。

表示例：

```text
バッテリー最大容量を記録すると、買い替えタイミングの判断に使えます。

設定アプリで確認できます。
設定 > バッテリー > バッテリーの状態と充電 > 最大容量

[入力する]
```

入力画面：

```text
バッテリー最大容量は何％ですか？

[ 86 ] %

確認日：2026年5月18日
```

### 5.3 バッテリー最大容量には確認日を必ず紐づける

バッテリー最大容量は時間によって変化するため、数値だけでは意味が弱い。

必ず確認日を保存・表示する。

例：

```text
バッテリー最大容量：86%
確認日：2026年5月18日
```

### 5.4 適度にアップデートを促す

バッテリー最大容量は定期的に更新してもらう。

初期MVPでは、最終確認から90日以上経過した場合に、マイiPhone上部のやることリストに更新タスクを表示する。

表示例：

```text
確認待ち

バッテリー最大容量の確認から3ヶ月経ちました。
今の状態を更新しますか？

[更新する]
```

## 6. 登録日・更新日の扱い

### 6.1 日付は必ず記録する

このアプリでは、iPhoneの状態が時間とともにどう変わるかが重要になる。

そのため、以下の日付を内部的に分けて持つ。

- 登録日
- 端末情報取得日
- バッテリー確認日
- 最終更新日

### 6.2 ユーザーに見せる日付

マイiPhone一覧・詳細では、最低限以下を表示する。

```text
登録日：2026年5月18日
最終更新：2026年5月18日
```

詳細画面では、必要に応じて以下も表示する。

```text
端末情報取得：2026年5月18日
バッテリー最大容量：86%（2026年5月18日確認）
```

## 7. 感想・使用感ログの設計

### 7.1 登録時には感想を聞かない

現在使っているiPhoneを追加する段階では、感想や満足度は聞かない。

まずはマイiPhoneに登録するだけにする。

感想・満足度・不満点は、後からタスクとして追加する。

### 7.2 感想は「レビュー」ではなく「使用感ログ」

このアプリでは、レビュー投稿を求めるのではなく、ユーザー自身のための使用感ログとして扱う。

UI上の表現は、以下を基本にする。

- いまの感想を残す
- 使用感を記録する
- 状態をチェックする
- このiPhone、今どうですか？

「レビューを書く」という表現は避ける。

### 7.3 1問ずつ答えるUIにする

使用感の追加画面は、通常のフォームではなく、1問ずつ答えていくインタビュー形式にする。

初期MVPの質問例：

1. 今もメインで使っている？
2. バッテリーに不満はある？
3. サイズ感は合っている？
4. カメラに満足している？
5. 容量に不満はある？
6. 次も同じサイズを選びたい？
7. ひとこと残す？

ただし、MVPではさらに絞ってもよい。

最小案：

1. 今も使っている？
2. いまの満足度は？
3. 気になるところは？
4. ひとこと残す？

### 7.4 感想は何度でも追加できる

使用感ログは1回だけのレビューではない。

時系列で複数回追加できる。

例：

```text
2026年5月：登録直後の感想
2026年8月：3ヶ月後の感想
2026年11月：バッテリー劣化後の感想
2027年1月：買い替え検討時の感想
```

これにより、iPhoneとの付き合い方や不満の変化が見える。

## 8. やることリスト・タスク設計

### 8.1 感想や不足情報はタスクとして見せる

このアプリでは、未入力情報をただの空欄として見せるのではなく、メルカリの「やることリスト」のように、潰したくなるタスクとして表示する。

ただし、圧をかけすぎず、さりげない未完了感に留める。

### 8.2 初期MVPのタスク

初期MVPでは、以下をタスク化する。

- バッテリー最大容量を入力する
- 今の使用感を記録する
- バッテリー最大容量を更新する

将来的には以下も検討する。

- 購入時期を入力する
- 購入価格を入力する
- 買い替え意向を記録する
- 過去に使っていたiPhoneを追加する
- 売却価格を記録する

### 8.3 マイiPhone上部にやることリストを置く

マイiPhone画面の上部に、確認待ちタスクをまとめて表示する。

例：

```text
やること

確認待ちの項目が2件あります
・バッテリー最大容量を入力
・今の使用感を記録

[まとめて確認する]
```

### 8.4 まとめて記録する導線

複数のタスクがある場合は、1つずつ詳細画面を開くのではなく、まとめて記録できるようにする。

例：

```text
1 / 2
バッテリー最大容量を入力

2 / 2
今の使用感を記録
```

タスクを潰すたびに残件数が減る。

## 9. 赤ドット・ステータス表示

### 9.1 一覧では赤ドット程度にする

マイiPhone一覧やカード上では、「感想待ち」「未入力」などの大きなバッジは出さない。

棚としての気持ちよさを壊さないため、未完了タスクがある場合は赤いドット程度で示す。

例：

```text
iPhone 16 Pro  ●
```

### 9.2 完了済みは基本的にドットなし

完了済みのものに緑ドットを常時出すと、画面がドットだらけになりやすい。

初期MVPでは、一覧では以下のルールにする。

- 未完了タスクあり：赤ドット
- タスクなし：ドットなし

詳細画面では、必要に応じて記録済み状態を表示する。

例：

```text
記録済み
最終更新：2026年5月18日
```

### 9.3 詳細画面で理由を説明する

一覧では赤ドットだけを見せ、詳細に入ったら理由を明示する。

例：

```text
確認待ち
・バッテリー最大容量
・今の使用感
```

## 11. iPhone追加画面

### 11.1 自動検出を主導線にする

iPhone特化MVPでは、現在端末の自動検出を最初の主導線にする。

ただし、過去のiPhoneやサブ端末を登録するために、手動追加画面も必要。

### 11.2 手動追加画面

手動追加画面では、たくさんのモデルがあっても綺麗に辿り着けるようにする。

構成案：

- iPhone 15
- iPhone 15 Pro

シリーズから探す
- iPhone 16シリーズ

- iPhone 14シリーズ
- iPhone SE

### 11.3 検索バーは上部に大きく置く

検索バーは画面上部に明確に置く。

プレースホルダー例：

```text

```

### 11.4 商品数を見せすぎない

- 検索

- シリーズから探す
- 過去モデル
- 手動入力

## 12. 探すタブ

### 12.1 探すタブの役割

探すタブは、次のiPhone選びのための場所。

初期MVPでは、以下を優先する。

- iPhoneモデル一覧
- シリーズ別ブラウズ
- 自分の現在端末との比較
- 買い替え候補の表示

### 12.2 比較表アプリにはしない

iPhone特化にしても、単なるスペック比較表アプリにすると弱い。

このアプリの主役は、商品スペックではなく、ユーザー自身のiPhone使用履歴と不満である。

探すタブでは、将来的に以下のような出し方を目指す。

```text
あなたは容量不足が出ています。
次は256GB以上を選ぶと安心です。

あなたはバッテリー劣化が進んでいます。
買い替えかバッテリー交換を検討してもよさそうです。

あなたはサイズ感に満足しています。
次も同じサイズ帯のモデルが合いそうです。
```

## 15. 体験の基本ループ

初期MVPで作りたい体験は以下。

```text
アプリを開く
↓
今のiPhoneが検出される
↓
マイiPhoneに追加する
↓
登録日つきで保存される
↓
赤ドットで確認待ちが残る
↓
バッテリー最大容量を入力する
↓
使用感を記録する
↓
マイiPhoneの情報が育つ
↓
一定期間後に更新タスクが出る
↓
iPhoneの状態変化が記録される
```

このループにより、ユーザーは自分のiPhoneの状態を少しずつ育てていける。

## 16. 現時点の設計判断まとめ

- ガジェット全般ではなく、iPhone特化にする
- 5タブではなく、2タブにする
- 設定は右上アイコンに逃がす
- 初回登録では何も聞かない
- 自動取得できる端末情報を使って登録を軽くする
- バッテリー劣化度は取得できないため、手入力にする
- バッテリー最大容量には確認日を必ず持たせる
- 感想・使用感はレビューではなくログとして扱う
- 未入力情報は赤ドットとやることリストで潰したくなる形にする
- 一覧では赤ドット程度のさりげなさに留める
- 登録日・最終更新日は必ず表示する
- 探すタブはスペック比較ではなく、使用履歴にもとづく買い替え判断に寄せる
